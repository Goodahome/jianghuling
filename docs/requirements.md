## 1. 产品概述

| 项 | 内容 |
|----|------|
| 项目名称 | 江湖令（JiangHuLing） |
| 品牌定位 | 江湖互助平台 |
| Slogan | 天下有悬赏，江湖有侠士。 |
| 品牌理念 | 江湖不让善意吃亏。 |
| 品牌愿景 | 帮助别人，也成就自己。 |
| 一句话定位 | 以悬赏协作为核心的江湖互助平台：有求可张贴悬赏令，有能可揭榜成侠士；平台托管赏银、协作结算、信誉护航。 |
| 与竞品差异 | 不是论坛、不是传统中介、不是普通跑腿；核心是「多人揭榜协作 + 赏银托管结算 + 声望成长」。 |
| MVP 聚焦 | **租房悬赏**（求租找房 + 房东/转租找租客，双场景） |
| 首发范围 | **遵义单城试点**；Web 响应式 |
| 目标用户 | 遵义有租房相关需求的令主；愿意接单协助的同城侠士；武林盟运营 |
| 要解决的问题 | 租房信息真假难辨、找人帮忙成本高、善意付出难获得对等回报；需要可托管、可协作、可评价、可仲裁的悬赏机制。 |

## 2. 用户角色（世界观映射）

| 业务角色 | 江湖称谓 | 说明 / 动机 | 核心权限（MVP） |
|----------|----------|-------------|-----------------|
| 注册用户 | 侠士 | 可发令也可揭榜；追求等级与上榜 | 邀请注册、登录、资料、实名、发令/揭榜、钱庄、评价、查看英雄谱、等级成长 |
| 发布人 | 令主 | 张贴悬赏、托管赏银、按贡献分配 | 创建悬赏、沟通、确认完结并全额分配、发起纠纷 |
| 揭榜人 | 揭榜侠士 | 参与协作、提交成果 | 一键揭榜、沟通、多次提交成果、评价令主 |
| 荣誉顶点 | **武林盟主** | 侠士等级与荣誉的最高目标；声望最高者可申请 | 荣誉权益；可推荐职司人选（无最终授予权） |
| 治理职司 | **令审使 / 验功使** 等 | 高等级侠士申请、管理员批准后的下放治理岗 | 对应审核等治理权限（见 6.13）；可被撤销 |
| 平台运营 | **武林盟**（管理员） | 系统所有者侧；掌握核心权限与监督权 | 核心配置、资金、任免、权限授予/撤销、仲裁终裁、全量后台 |
| AI 助手 | 百晓生 | 智能辅助 | **不进 MVP**（P2） |
| 企业客户 | 商号 | 企业悬赏 | **范围外（第三阶段）** |

**说明**：

- 同一账号可同时为令主与揭榜侠士；权限随具体悬赏令上的参与身份变化。
- **武林盟** = 管理员体系；**武林盟主** = C 端最高荣誉；**职司** = 可下放的治理权限载体。
- 不是所有事都由管理员亲力亲为：日常审核等可由职司承担，管理员监督。

## 3. 已确认产品决策（冻结）

| # | 议题 | 决策 |
|---|------|------|
| 1 | 租房场景 | **A3**：求租发令 + 房东/转租发令 都做 |
| 2 | 首发城市 | **遵义**单城 |
| 3 | 揭榜规则 | **点了即加入**；无需令主审核；单令侧 **揭榜人数无上限**；个人侧见 #17–#19 |
| 4 | 支付 | MVP **模拟钱庄**（托管/结算走模拟，**不接真实支付**）；用户充值/提现 **暂时隐藏**（见 #31）；银两来源见 #31 |
| 5 | 实名 | 提供实名认证能力；**暂不作发令硬门槛** |

| 7 | 零两分配 | 允许给某人分 **0 两**；可选额外给予侠义值；**无需签收确认，自动到账** |
| 8 | 纠纷时限 | 争议发起窗口 **7 天**（自可发起节点起算，见流程） |
| 9 | 超时 | 截止前 **提醒**；超时后 **自动取消悬赏并全额退款**（托管解冻退回令主）。【v1.8.8 修订】待验收 `PENDING_SETTLE` 超时不再取消，改走 **超时自动完结** → 分配页面（见 #40、§6.23.4） |
| 10 | 端形态 | MVP **仅 Web**（响应式） |
| 11 | 登录 | **手机验证码** 或 **账号密码**，两者可选 |
| 12 | 百晓生 | **不进 MVP** |
| 20 | 注册准入 | MVP **仅邀请注册**：必须持有有效邀请码/邀请链接才能注册；无公开自助注册 |
| 13 | 侠义值 | 可兑换奖品；**揭榜本身不发侠义值**，须与有效贡献/审核通过挂钩，防白嫖刷分 |
| 14 | 江湖声望 | MVP 采用 **好评率 + 完成单量** |
| 15 | 反作弊审核 | 增加 **发令审核** + **揭榜人成果审核**，防恶意发令/揭榜刷侠义值等 |
| 16 | 成果提交 | 揭榜人可 **多次提交**；须 **限流/防批量恶意提交** |
| 17 | 揭榜日上限 | 同一侠士 **每天揭榜不超过 10 次**（自然日，可配置） |
| 18 | 同令唯一 | 同一侠士对 **同一悬赏令只能揭榜 1 次**（不可重复揭榜） |
| 19 | 体力值 | 新增 **体力值**：每次揭榜消耗体力；可用 **侠义值兑换体力**；即使体力充足，仍受每日揭榜 ≤10 约束 |
| 21 | 后台完整性 | MVP 必须具备 **完整武林盟后台**（用户、业务、财务流水、运营配置、系统管理等），不只是零散审核页 |
| 22 | 等级体系 | 侠士多级头衔；**武林盟主为最高目标**；前序等级由侠义值晋升，盟主位需声望申请+审核 |
| 23 | 英雄排行榜 | C 端展示武侠主题排行；**界面展示名「英雄榜」**（文档/术语可仍称英雄谱）；含声望榜等；盟主荣耀展示 |
| 24 | 盟主产生 | **江湖声望最高**（默认排名第 1）的侠士可申请成为武林盟主；武林盟后台审批；同时仅 1 任 |
| 25 | 权限分层 | **核心权限**仅管理员；**治理权限**可由达标等级侠士申请职司获得；管理员可监督、改判、撤销；职司无核心权限 |
| 26 | 职司申请 | 达到指定等级可申请对应职司；**是否授予由管理员决定**；可设人数上限与任期 |

## 6. 关键业务流程

### 6.1 邀请注册与登录

1. **MVP 无公开注册**：未持有效邀请不可创建账号；注册页必须填写/携带邀请码（或通过邀请链接进入并自动带码）。
2. 邀请校验通过后，再完成：手机验证码注册，或账号密码注册。
3. 注册成功后绑定邀请关系（邀请人、被邀请人），供运营追溯；邀请码核销规则见待细化备注。
4. **登录**不需要邀请码：已注册侠士可用手机验证码或账号密码登录。
5. 完善昵称、头像、简介等；城市默认遵义。
6. 可进行实名认证（MVP 不阻断发令/揭榜）。
7. 种子用户：由武林盟后台直接创建账号或发放首批邀请码冷启动。
8. **注册成功资金动作（v1.7）**：
   - 为新用户钱庄入账 **500 两**（流水类型：注册赠银）；
   - 若存在有效邀请人：为邀请人入账 **100 两**（流水类型：邀新奖励）；同一被邀请人仅触发一次；
   - 向相关方发送站内消息告知到账。

### 6.1.1 模拟钱庄银两来源（v1.7）

| 来源 | 金额（默认） | 触发 | 操作方 |
|------|--------------|------|--------|
| 注册赠银 | 500 两 | 注册成功 | 系统 |
| 邀新奖励 | 100 两 | 被邀请人注册成功 | 系统 → **邀请人** |
| 管理员发放 | 自定义 | 后台调账/发放 | 武林盟管理员（须审计） |
| 悬赏结算入账 | 按分配 | 结算成功 | 系统 |
| 悬赏退款解冻 | 按托管 | 驳回/超时取消等 | 系统 |

**MVP 用户端（暂时隐藏，非永久删除）**：

- 充值、提现入口默认 **不展示、不可用**（前端隐藏；用户侧接口可返回「暂未开放」或由配置关闭）。
- **能力保留**：代码/接口不删，待真实支付或运营打开开关后恢复。
- 建议系统参数：`wallet.rechargeEnabled=false`、`wallet.withdrawEnabled=false`（后台可改，默认 false）。

钱庄页仍展示：余额、冻结、流水；文案标明「模拟银两，由平台发放与悬赏流转」。  
管理员「发放/调账」保留，须填原因并记审计日志。

### 6.2 张贴悬赏令（结构化令状 + 审核与托管）

1. 令主选择令状类型：**求租令状** 或 **出租/转租令状**（不可自由散文发令替代模板）。
2. 按模板填写结构化字段（见下表）；选择 **任务标签/难易度**，系统展示 **建议赏银**。
3. 填写赏银（单位：**两**）：须 ≥ **200 两**（硬性）；若低于当前难度建议下限，弹出强提示「赏银偏低，恐无人揭榜 / 有违江湖不让善意吃亏」，可改金额或确认坚持（仍不得低于 200）。
4. 勾选本单适用的 **探子清单** 项（部分按标签预勾，可增删；核心项可配置为必选）。
5. 提交时从模拟钱庄冻结赏银（余额不足则不可提交）。
6. 进入 **待审核**；令审使/管理员通过 → **张贴中**；驳回 → 解冻退回并通知原因。
7. 审核通过前不在广场展示，不可揭榜。

### 6.2.1 赏银建议与最低赏银（两）

**货币约定（MVP）**：钱庄余额与悬赏赏银统一用 **两** 展示（文案标明「模拟银两」）。现实「房租」字段仍用 **元/月**，与赏银分离。用户充值/提现 MVP 隐藏；若后台临时打开模拟充值，可按 1:1 入账为两。

| 难易度 | 典型场景 | 建议赏银（两） | 规则 |
|--------|----------|----------------|------|
| 简易 | 线上问询、单点信息核验、转发对接 | **200～300** | 建议下限 200 |
| 普通 | 1 次上门带看、基础验房 | **300～500** |  |
| 艰辛 | 多套房带看、深度验房、急单（≤48h） | **500～800** |  |
| 超难 | 全城寻房打包、多日跟进、复杂核验 | **800～1500+** | 可上不封顶 |

**校验逻辑**：

1. **硬拦截**：赏银 `< 200` → 禁止提交。  
2. **建议提示**：赏银 `< 当前难度建议下限` → 强提示，须二次确认才可提交（且仍 ≥200）。  
3. **正向文案**：展示「建议赏银覆盖交通与时间成本，江湖不让善意吃亏」。  
4. 后台可调整：全局最低赏银、各难度建议区间；令审使审核时可因「赏银与难度明显不符」驳回（可选策略）。

### 6.3 揭榜与协作

1. 侠士在广场浏览详情后 **一键揭榜**，即时成为揭榜侠士（无需令主同意；**单令揭榜人数无上限**）。
2. 揭榜前校验（任一失败则不可揭榜，并提示原因）：
   - 非本人发布的、状态为可揭榜的悬赏令
   - **未曾对该令揭榜**（同令仅 1 次）
   - **当日已揭榜次数 < 10**
   - **体力值 ≥ 本次消耗**（默认每次 1 点）
3. 揭榜成功：扣减体力 1 点；当日揭榜次数 +1；建立揭榜关系。
4. **揭榜动作本身不发放侠义值、不增加完成单量。**
5. 令主与揭榜侠士站内沟通；侠士线下/线上协助。
6. 协作中侠士可 **退出揭榜**（v1.8.8）：体力返还、当日揭榜次数不返还、同令不可再揭（见 §6.23.5）。

### 6.3.1 体力值

1. 体力用于揭榜消耗；展示当前体力、今日已揭榜次数 / 上限。
2. **每日恢复**：自然日重置时，将体力恢复至「每日免费体力」（建议默认 **5**，可配置）；已高于该值的不因重置被削（若采用「仅补足」策略则补到免费额度即可）。
3. **侠义值兑换体力**：侠士可按汇率兑换（建议默认 **10 侠义值 = 1 体力**，可配置）；兑换后体力增加，但 **仍不能突破每日揭榜 10 次硬上限**。
4. 设计意图：免费体力 < 日上限时，活跃侠士需消耗侠义值兑换体力才能接近 10 次/日，提高恶意刷榜成本。
5. 武林盟可配置：每日免费体力、揭榜日上限、单次揭榜耗体、兑换汇率。
6. **退出揭榜返还（v1.8.8）**：侠士退出揭榜时返还该次揭榜所耗体力（默认 1 点）；**当日已揭榜次数不随退出抹减**（防刷硬口径，见 §6.23.5）。

### 6.4 成果提交（可多次 + 防刷 + 审核）

1. 揭榜侠士可提交成果，**同一揭榜关系允许多次提交**（版本列表供审核/令主查看）。
2. 成果须尽量按本单 **探子清单** 逐项填写/上传（见 6.4.1）。
3. **防恶意批量提交（MVP 规则）**：
   - 同一揭榜关系提交冷却（建议默认 ≥ 10 分钟，可配置）
   - 同一侠士全站每日提交上限（建议默认 ≤ 30 次/日，可配置）
   - 短时窗口限流（如 1 分钟内 ≤ 2 次）
   - 空内容/过短内容拒绝；重复度极高的连发可拒绝或进人工
4. 每次有效提交进入 **成果待审核**；验功使/管理员通过/驳回。
5. **仅「审核通过」的成果** 可作为结算时有效贡献依据，并作为侠义值发放的前提之一。

### 6.4.1 探子清单（验核 Checklist）

1. **定义**：与租房任务绑定的结构化检查项；武侠名「探子清单」，界面同时显示白话说明。
2. **发令侧**：令主基于任务标签预填清单，可勾选；标记为「必验」的项揭榜人提交时必须覆盖。
3. **揭榜侧**：提交成果时按项勾选完成情况，并上传对应说明/图片；未完成必验项不可提交或提交后默认难以通过审核。
4. **审核侧**：验功使对照清单验收；可单项驳回意见。
5. **默认清单库（可后台配置）**：

| 清单项 | 适用标签示例 | 提交要求示例 |
|--------|--------------|--------------|
| 房源真伪核验 | 帮核验真伪、帮寻房 | 中介/房东沟通摘要、可疑点说明 |
| 产权/转租合规问询 | 帮验房、帮核验 | 询问记录说明（勿引导违法获取证件原件） |
| 水电燃气与物业 | 帮验房、帮带看 | 照片或文字确认 |
| 屋况与设施 | 帮验房、帮带看 | 厨房卫生间、漏水霉变等 |
| 周边与通勤 | 帮带看、帮寻房 | 文字说明到关键地标耗时 |
| 租金与费用构成 | 帮谈价、帮寻房 | 押金、中介费、物业费是否说清 |
| 带看事实记录 | 帮带看 | 带看时间、小区名、接待方（脱敏） |
| 意向租客初步筛 | 帮找租客 | 意向、入住时间、是否看房（出租令） |

6. 清单库与「任务标签 → 默认项」映射由武林盟后台维护。

### 6.5 分配赏银与结算

1. 令主在存在可结算条件时发起完结（至少建议：有揭榜人且存在审核通过的成果；细则见待细化备注）。
2. **资金公式**：
   - 托管赏银 = 令主冻结金额 `B`
   - 平台服务费 = `B × 10%`
   - **可分配池** = `B × 90%`
   - 令主分配给各揭榜侠士的金额之和必须 **等于可分配池**（分完才能提交结算）
3. 允许给某人 **0 两**；可同时勾选给予一定 **侠义值奖励**（来自平台规则额度，非从赏银折算，额度与发放条件由武林盟配置）。
4. 提交结算后 **自动签收到账**（模拟钱庄入账），无需侠士确认。
5. 结算成功后开放互评；更新完成单量与好评率（江湖声望）。

### 6.6 超时取消

1. 截止前发送提醒（如 T-24h、T-2h，可配置）。
2. 到达截止仍未成功结算 → **自动取消**：托管全额退回令主；揭榜关系结束；不产生完成单（已产生的审核记录可保留审计）。
3. **【v1.8.8 变更】** 待验收 `PENDING_SETTLE` **不纳入超时自动取消**：到期走 **超时自动完结** → 分配页面分配冻结赏银（见 §6.23.4）；上条自动取消仅覆盖 `PENDING_REVIEW` / `OPEN` / `IN_COLLAB`。

### 6.7 纠纷仲裁

1. 自「结算完成」或「争议可发起节点」起 **7 天内** 可发起纠纷并举证。
2. 武林盟裁决：维持结算 / 调整分配 / 退回 / 处罚（声望、封禁等）。
3. 裁决后资金按结果在模拟钱庄执行，令主不可单方再改。
4. **取消引发的争议**走「取消争议」工单（v1.8.8 新增，见 §6.23.6）：窗口、队列与裁决口径对齐本节 7 天惯例。

### 6.8 侠义值与兑换

1. **不发放**：仅揭榜、仅灌水提交、审核驳回、超时取消且无有效贡献。
2. **可发放**（需同时满足风控）：成果审核通过，且/或令主在结算时授予；禁止「无审核通过成果却靠互刷发令揭榜」获得。
3. 侠义值用途：
   - 商城兑换奖品（武林盟配置奖品与库存）
   - **兑换体力值**（用于继续揭榜，仍受日揭榜上限约束）
4. 武林盟可对异常账号扣减侠义值/体力、取消兑换、封禁。

### 6.9 悬赏状态机（MVP / v1.8）

主路径：

`待审核(PENDING_REVIEW)` → `张贴中(OPEN)` → `协作中(IN_COLLAB)` → `待结算(PENDING_SETTLE)` → `已完结(COMPLETED)`

分支：

- `审核驳回(REJECTED)` ← 待审核驳回（退托管）
- `已取消(CANCELLED)` ← 令主取消 / 超时（**不含待验收 `PENDING_SETTLE`**，v1.8.8）/ 管理员强制关闭（**含纠纷中强制关闭**，v1.8.8）（退托管，若仍有冻结；令主取消且已有成果提交的改走分配页面，见 §6.23.3）
- **超时自动完结（v1.8.8）**：`待验收(PENDING_SETTLE)` 到截止未结算 → 系统自动完结并进入分配页面 → 令主分配后 → `已完结(COMPLETED)`（见 §6.23.4）
- `纠纷中(IN_DISPUTE)` ← 结算后争议 → 裁决后回到 `已完结` 或维持资金结果（按裁决）

**再发一令（v1.8）**：从 `REJECTED` / `CANCELLED` / `COMPLETED` 可触发「复制新建」→ 新单进入 `PENDING_REVIEW`（见 6.18）。原单状态不变，仅作历史。

### 6.18 再发一令（重新发布 · v1.8）

1. **入口**：令主在「我发布的」详情/列表，对状态为 `REJECTED` / `CANCELLED` / `COMPLETED` 的悬赏展示 **再发一令**。
2. **行为**：基于原令 **复制新建**（新悬赏 ID），预填：类型、标题、令状字段、任务标签、难易度、探子清单勾选、建议赏银等；**不复制**揭榜关系、会话、成果、评价。
3. **资金**：须令主再次确认赏银并 **重新冻结托管**（余额不足不可提交）；原单资金互不影响。
4. **审核**：新单一律进入 `PENDING_REVIEW`，与普通新发令相同（不可跳过审核）。
5. **截止时间**：默认按原规则重算或由令主重选（实现默认：打开发布页预填，令主确认截止日）。
6. **追溯**：新单可记录 `sourceBountyId`（来源令 ID），便于运营与纠纷排查。
7. **不可再发**：非本人令主；非上述终态；账号封禁等。

- 使用目的（服务提供、安全风控、审核职司、通知等）；  
- 平台内可见性与管理员/职司访问边界；  
- 存储与安全、保留原则；  
- 用户权利（查阅、更正、注销申请等）；  
- 未成年人；  
- 政策更新与联系渠道。

#### 6.21.4 变更与重新同意

1. 条款修订须更新文档版本号，页脚或文首可感知。  
2. **重大变更**（扩大收集范围、改变共享规则、重大免责调整等）：下次登录或进入注册相关流程时提示阅读，必要时要求重新勾选同意后方可继续核心服务（实现细节交前端/架构，产品要求「不可静默重大变更」）。  
3. 非重大排版润色可只公示不强制重勾。

### 6.22 全端页面层级与返回按钮（v1.8.6 · 侠士端 / 执事堂 / 武林盟）

> 适用范围：**侠士端（Hero）**、**执事堂（Hall）**、**武林盟后台（Admin）** 三端一致。  
> 问题：协作会话、提交成果等子页无页内返回；后台/执事堂下钻页亦须统一自查。  
> 规则：以「相对该端主导航的进入深度」分级；**二级起强制返回，三级及更深同要求**。

#### 6.22.1 层级定义（三端通用）

| 层级 | 定义 | 页内返回 |
|------|------|----------|
| **一级** | 该端顶栏 / 底栏 / **侧栏菜单**可直接进入的入口页 | **可不放**（可用导航离开） |

| **三级** | 从二级再进入的任务 / 会话 / 提交 / 结算 / 子详情等 | **必须有** |
| **更深** | 继续下钻页，或独立成功停留页 | **必须有**（或成功页提供明确去向 CTA） |

**弹层说明**：若详情/编辑仅以 Dialog/Drawer 呈现且带明显关闭，可视为已提供「返回」；一旦改为 **独立路由页** 或全屏子页，必须按二级+ 补页内返回。

#### 6.22.5 交互与实现约束（产品口径）

1. 返回控件须在 **页面内容区内可见**（页眉旁或内容顶栏），不可仅依赖浏览器后退。  
2. 文案：「返回」「返回上一页」「返回列表」「返回悬赏详情」等，语义清楚即可（后台可用「返回列表」）。  
3. 优先 **明确父路由**；无稳定父级时用 `history.back`，无历史则回该端安全页（广场 / 执事堂首页 / `/admin`）。  
4. 三端均须 **按路由表 + 实际下钻交互自查二级、三级及更深**，缺则补；不限于上文枚举。  
5. 样式随各端：侠士端/执事堂跟江湖视觉；后台跟 Admin 现有组件即可；可抽共用轻量返回条，不强制三端同一组件。

### 6.23 悬赏取消规则（v1.8.7）

> 目标：把「谁能取消、何时能取消、取消后赏银与信誉怎么办、争议去哪」收口为一节。  
> 标注约定：**【现状】** = 现有实现已具备；**【新增】/【变更】** = v1.8.7/v1.8.8 新提要求，待落地；原 §6.23.7 六项待确认已于 **2026-08-06 全部确认**（留痕见该节）。  
> 文案口径：资金与规则按 §14.1「钱与法用法语」，关键提示用现代汉语。

#### 6.23.1 谁可取消

| 角色 | 江湖称谓 | 对悬赏的取消权 | 入口 |
|------|----------|----------------|------|
| 发布人 | 令主 | 可取消 **本人发布且未完结** 的悬赏（状态范围见 6.23.2）【现状】 | 悬赏详情 / 我发布的 →「取消悬赏」（现状接口 `POST /api/v1/bounties/{id}/cancel`） |
| 接单人 | 揭榜侠士 | **无悬赏取消权**；悬赏是否终止由令主、超时规则、武林盟决定。中止协作的过渡做法与「退出揭榜」能力见 6.23.5 | 无取消入口 |
| 平台运营 | 武林盟（管理员） | 可 **强制关闭** 任一非终态悬赏；属风控/治理手段，**须填原因并落审计日志**【现状】 | 武林盟后台 → 悬赏管理 |

规则：

1. **职司无取消权**：令审使/验功使不可取消或关闭悬赏；强制关闭归管理员（依 §6.13 权限分层）。
2. **超时取消**由系统自动触发【现状 Job】，属平台规则行为，不算任何用户的主动取消；【v1.8.8】待验收 `PENDING_SETTLE` 超时改走 **自动完结**（§6.23.4），不计取消。
3. 取消一经生效 **不可逆**；仍需求助走 **再发一令**（§6.18：复制新建 + 重新托管 + 重新审核）。

#### 6.23.2 各状态能否取消（状态矩阵）

状态名对齐 §6.9；括号内为广场/详情界面语境。

| 悬赏状态 | 令主主动取消 | 超时自动取消 | 武林盟强制关闭 | 取消后赏银 |
|----------|--------------|--------------|----------------|------------|
| 待审核 `PENDING_REVIEW` | 可（视同撤回发令）【现状】 | 覆盖【现状】 | 可【现状】 | 全额解冻退回令主 |
| 张贴中（待接单）`OPEN` | 可【现状】 | 覆盖【现状】 | 可【现状】 | 全额退回 |
| 协作中（进行中）`IN_COLLAB` | 可【现状】；已有揭榜或审核通过成果时 **必填原因**【新增】 | 覆盖【现状】 | 可【现状】 | **已有成果提交**：进分配页面由令主手动分配冻结赏银【新增 · §6.23.3 #3】；**无成果提交**：全额退回、无补偿【已确认】 |
| 待验收（待结算）`PENDING_SETTLE` | 可【现状】；**必填原因**【新增】 | **不纳入超时自动取消**【已确认】；超时改走 **自动完结** → 分配页面【新增/变更 · §6.23.4】 | 可【现状】 | 待验收必有成果提交 → 取消进分配页面分配冻结赏银（计 10% 服务费）【变更 · §6.23.3 #3】 |
| 已完成 `COMPLETED` | 不可（终态） | — | 不可（终态）【现状】 | 已结算；异议走纠纷仲裁（§6.7） |
| 已取消 `CANCELLED` | 不可（终态；可再发一令 §6.18） | — | 不可【现状】 | 已退回 |
| 审核驳回 `REJECTED` | 不可（终态；可再发一令） | — | 无需【现状】 | 驳回时已退回 |
| 纠纷中 `IN_DISPUTE` | 不可单方取消 | — | **可【v1.8.8 变更】**：必填原因 + 审计；资金处置（退回令主 / 按裁决分配）随关闭单载明；现状实现若拦截须放开 | 按裁决或强制关闭载明处置（§6.7） |

#### 6.23.3 取消后的赏银处理

1. **总原则（v1.8.8 起按「是否有成果提交」分支）**：悬赏未结算即取消时，先判本令是否已有成果提交：
   - **无成果提交**：托管赏银 **全额解冻退回令主钱庄**（与 §3 #9、§6.6 一致；现状退款已幂等），揭榜侠士 **无任何奖励/补偿**【已确认】。
   - **已有成果提交**（令主在协作中/待验收主动取消）【新增】：不全退，冻结赏银转入 **分配页面** 由令主手动分配（见 #3）。
   - 本补偿分支适用 **令主主动取消**；超时自动取消与武林盟强制关闭维持全额退回口径，揭榜侠士有异议走「取消争议」工单（§6.23.6）。
2. **服务费**：无成果取消未成交，不收取 10% 服务费；有成果取消进分配的，按 §6.5 公式计提 10%（视同结算资金口径）【新增】。
3. **有成果取消的分配规则【v1.8.8 新增】**：
   - 触发：令主在协作中/待验收取消，且本令已存在 ≥1 条成果提交记录（任一揭榜侠士）。
   - 取消生效后悬赏进入 **分配页面**（复用 §6.5 完结分配入口与交互）；令主仅可向 **有成果提交的揭榜侠士** 分配。
   - 资金公式沿用 §6.5：服务费 10%、可分配池 90%、须 **100% 分完**、允许 0 两、提交后自动到账。
   - 分配完成前资金保持冻结；分配完成后解冻结算，悬赏维持 **已取消** 终态（不改为已完结）。
   - 建议设 **分配宽限期 7 天**（可配，§13 登记）；逾期武林盟可督办，建议兜底：按审核通过成果在提交侠士间均分可分配池并结案（后台可配开关）。
4. **违约金 / 扣款**：MVP **不设违约金、不从托管赏银扣罚**【v1.8.8 再确认】——无成果取消即全退，有成果取消即分完（与 §13「仅允许走取消退款，不可空分」的善意基调一致）。
5. **信誉影响（v1.8.8 已确认）**：
   - 待审核撤回、张贴中取消（无揭榜）、超时取消：正常流转，仅登记，**不记负面**。
   - 令主每次主动取消均 **登记取消次数**（含取消时状态、原因、是否有成果，留审计）。
   - **有揭榜后的取消**（协作中/待验收）：计入声望负向——建议默认 **每单 -10 声望分**（与 §13 声望公式 `完成单量×10 + 好评率×100` 同量级，约抵销 1 个完成单正向权重；后台可配，§13 登记）。
   - 建议（可配）：令主资料/悬赏详情对揭榜侠士展示近 90 天取消次数，供揭榜前参考。
6. 取消单 **不产生完成单量**、不开放互评（含分配补偿的取消单：资金可分，完成单量与互评仍不开放）；已产生的审核记录保留审计（§6.6 同口径）。**超时自动完结** 的单按正常完结口径产完成单量与互评（§6.23.4）。

#### 6.23.4 取消申请与确认流程

1. **令主取消**：
   - 入口：悬赏详情 / 我发布的；仅未完结状态展示「取消悬赏」。
   - **二次确认【新增】**：弹窗按是否有成果提交区分文案【v1.8.8】——无成果：「赏银将全额退回钱庄，揭榜协作即行终止，取消不可撤销」；已有成果：「本令已有成果提交，取消后须进入分配页面分配冻结赏银（平台计提 10% 服务费），取消不可撤销」。
   - **取消原因**：待审核/张贴中可简填；**协作中 / 待验收必填原因【新增】**（现状后端允许空原因并默认「令主取消」）。
   - 生效【v1.8.8 变更】：先 **登记令主取消次数**（§6.23.3 #5）→ 判成果分支：无成果 → 托管全额解冻退回；有成果 → 冻结赏银转入 **分配页面**（§6.23.3 #3）→ **站内通知令主与全体揭榜侠士【通知揭榜侠士为新增，现状仅通知令主】**。
   - 通知文案须含：悬赏标题、取消方（令主 / 超时 / 武林盟）、原因、赏银去向（全额退回 / 待分配）。
2. **超时（v1.8.8 起分态处理）**：
   - `PENDING_REVIEW` / `OPEN` / `IN_COLLAB`：维持 **超时自动取消** + 全额退回【现状】；补通知揭榜侠士【新增】。
   - `PENDING_SETTLE`【新增/变更】：**不再自动取消**；到期触发 **超时自动完结**——系统自动将悬赏推进结算，令主须在 **分配页面** 完成冻结赏银分配（§6.5 公式；宽限期与兜底同 §6.23.3 #3）；分配完成后状态 → `COMPLETED`，按正常完结口径产完成单量并开放互评；通知令主与全体揭榜侠士【新增】。
3. **武林盟强制关闭**：后台操作，**必填原因 + 审计日志**；退款幂等【现状】；通知令主【现状】+ 揭榜侠士【新增】。【v1.8.8】**纠纷中 `IN_DISPUTE` 亦可强制关闭**（见 §6.23.2）；涉及已提交成果或纠纷单的，资金处置（退回令主 / 按裁决分配）须在关闭原因与审计中载明。
4. **取消不可逆**：成功后不可恢复原单；继续求助走再发一令（§6.18）。

#### 6.23.5 揭榜侠士侧：中止协作与「退出揭榜」

1. 揭榜侠士 **不能取消悬赏**（6.23.1）；其劳动保护依赖：成果审核记录、取消原因必填、取消通知、有成果取消的分配补偿（§6.23.3 #3）、争议通道（6.23.6）。
2. **退出揭榜【v1.8.8 新增，已确认提供】**：悬赏未终态（协作中）时，揭榜侠士可 **单方退出揭榜关系**：
   - 入口：悬赏详情 / 协作会话；须 **二次确认**（明示「退出后不可再揭本令，已提交成果保留审计」）。
   - **体力返还**：返还本次揭榜所耗体力（默认 1 点，对齐 §6.3.1 单次耗体口径）。
   - **当日揭榜次数不返还**：日揭榜次数是防刷硬口径（§3 #17），若返还可借「揭榜→退出」循环绕过日上限；与体力机制的设计意图（§6.3.1 #4）一致。
   - **同令不可再揭**（§3 #18 同令一次口径不变）；退出后可揭其他令（仍受日限与体力约束）。
   - 退出后：揭榜关系终止，不可再提交成果；已提交的成果记录保留审计；站内 **通知令主**【新增】。
   - 频繁退出：登记退出次数留审计；MVP 不做自动信誉扣罚（若滥用再立项，方向对齐令主取消登记）。
3. **推荐先沟通**：侠士想中止协作时，仍建议先在协作会话向令主说明再退出（江湖体面，非强制）。

#### 6.23.6 取消相关争议入口

1. **已完结单** 的争议：维持既有纠纷仲裁（§6.7，结算完成后 7 天窗口）。
2. **「取消争议」工单【v1.8.8 新增，已确认】**：
   - 适用场景：取消引发的争议——协作中/待验收被令主取消（补偿诉求）、对取消后分配结果不服、对强制关闭不服等。
   - 发起窗口：自 **取消生效**（未进分配的）或 **分配完成**（进分配的）起 **7 天**（对齐 §6.7 纠纷 7 天惯例；建议默认，可配，§13 登记）。
   - 通道与处理：与纠纷仲裁同队列——武林盟工单队列、举证材料、裁决与执行；MVP 由管理员终裁（L0）；职司初调归 P1 调解使（§6.13.3）。
   - 裁决选项：维持 / 调整分配 / 补发侠义值 / 声望与处罚（同 §6.7 口径）。
   - 次级建议值：工单类型枚举建议 `CANCEL_DISPUTE`，字段复用纠纷工单（细节交 @architect）。
3. **对强制关闭不服**：令主可经「取消争议」工单或站内通道申诉，武林盟复核并终裁；关闭原因与审计留痕可回查。

| 2 | 江湖新锐 | 100 |  |

### 6.11 英雄谱（排行榜）

1. C 端排行榜正式名称：**英雄谱**（副文案示例：「谁是遵义最义侠」）。
2. MVP 至少包含以下子榜（页签）：
   - **声望榜**：按江湖声望分排序
   - **侠义榜**：按累计侠义值排序
   - **完令榜**：按完成悬赏单量排序
3. 展示：排名、头像、昵称、头衔、关键数值；**现任武林盟主**在声望榜荣耀位固定露出（榜首金名或谱首专区）。
4. 刷新：近实时或定时（建议每 10 分钟），后台可配置。
5. 仅统计正常未封禁账号；遵义试点下单城即全站榜。

### 6.12 武林盟主申请与任免

1. **申请资格（默认）**：当前 **声望榜第 1** 且账号正常；非现任盟主；无严重处罚记录。
2. 申请人提交说明 → 武林盟后台「盟主申请」队列。
3. 审批通过：原盟主（若有）卸任并回落头衔；新盟主生效；全局 **同时仅 1 任**。
4. 审批驳回：保持原状；默认 7 天冷却后可再申请。
5. 武林盟可主动罢免（严重违规），须填原因并记审计日志。
6. 盟主 MVP 权益（轻量）：专属标识、英雄谱荣耀展示、每日免费体力 +2（可配）。
7. **武林盟主 ≠ 后台管理员**：C 端荣誉头衔不自动授予核心权限；盟主可 **推荐** 职司候选人，最终授予仍由管理员决定。

### 6.13 系统权限分层与职司（关键）

> 目标：管理员不包办一切日常治理；高等级侠士可申请治理权；**核心权限始终由管理员掌握**。

#### 6.13.1 三层权限模型

| 层级 | 名称 | 谁拥有 | 如何获得 | 可否被撤销 |
|------|------|--------|----------|------------|
| L0 | **核心权限** | 仅武林盟管理员（系统账号） | 后台角色配置，管理员体系内分配 | 管理员体系内调整 |
| L1 | **治理权限** | 持有职司的侠士 | **等级达标 → 申请 → 管理员批准** | **管理员可随时暂停/撤销** |
| L2 | **基础权限** | 全体侠士 | 注册/等级自动附带 | 封禁等风控手段限制 |

另：**荣誉权限**（武林盟主）属 L2 增强展示 + 轻量建议权，**不包含 L0**，也不默认包含全部 L1。

#### 6.13.2 核心权限（L0，不可下放给侠士）

以下必须由管理员决定/执行，职司与盟主均不可拥有：

- 系统参数、费率、字典、菜单与管理员账号 RBAC
- 模拟钱庄调账、强制资金处置策略配置、服务费规则变更
- 用户永久封禁/解封策略终裁；资产（侠义值/体力/余额）**手工调整**
- **职司的授予、暂停、撤销** 与名额/门槛配置
- **武林盟主任免终审与罢免**
- 纠纷 **终裁**（可改判职司或下级处理结果）
- 查看完整敏感数据导出、安全审计配置

#### 6.13.3 治理权限（L1，可申请下放）—— MVP 职司表

| 职司 | 江湖称谓 | 申请门槛（默认） | 可做什么 | 不可做什么 |
|------|----------|------------------|----------|------------|
| 发令审核 | **令审使** | ≥ 一代大侠（Lv5）且近 30 日无严重处罚 | 审核发令：通过/驳回并填原因 | 改资金、封禁用户、改系统配置 |
| 成果审核 | **验功使** | ≥ 一代大侠（Lv5）且近 30 日无严重处罚 | 审核成果：通过/驳回并填原因 | 同上；不可给自己/利益关联单审核（见回避） |
| （P1）调解 | **调解使** | ≥ 宗师境 | 小额/简单纠纷初调建议 | 无终裁权；终裁归管理员 |

规则：

1. **名额**：每类职司设上限（默认各 10 人，可配）；满员不可再批。
2. **任期**：默认 90 天，到期需续任申请；管理员可提前撤。
3. **回避**：不可审核自己发的令、自己揭榜的令、直属邀请上下级相关单（MVP 至少：本人关联悬赏）。
4. **激励（可选轻量）**：有效履职可获少量侠义值，须防刷，由管理员配开关与上限。

#### 6.13.4 基础权限（L2）随等级变化（示例）

| 能力 | 初入江湖～仗义行侠 | 名动一方+ | 一代大侠+ | 宗师境 / 盟主 |
|------|-------------------|-----------|-----------|---------------|
| 发令/揭榜/结算等主流程 | ✓ | ✓ | ✓ | ✓ |
| 每日邀请码额度 | 基础 | 略增 | 更高 | 最高档（可配） |
| 申请令审使/验功使 | ✗ | ✗ | ✓（可申请） | ✓ |
| 申请武林盟主 | 仅声望榜规则 | 同左 | 同左 | 同左 |
| 推荐职司候选人 | ✗ | ✗ | ✗ | 盟主可推荐 |

> 具体数值放后台配置；上表表达「等级越高，可申请的治理权越多」，**不是自动拥有审核权**。

#### 6.13.5 申请 → 授权 → 监督 → 撤销

```
等级达标 → 提交职司申请 → 管理员审批（可参考盟主推荐）
    → 授予职司（写入权限 + 任期）
    → 在「执事堂」处理队列（全量操作日志）
    → 管理员抽检 / 用户申诉 / 被改判
    → 暂停或撤销职司（管理员一键生效）
```

监督指标（后台可见）：处理量、通过/驳回比、被管理员改判率、投诉率。  
默认：近 7 日改判率过高或严重违规 → 系统建议暂停，**是否暂停仍由管理员确认**（也可配置自动暂停）。

#### 6.13.6 管理员角色（后台 RBAC，L0 内部再拆）

| 管理员角色 | 职责 |
|------------|------|
| 超级管理员 | 全部 L0；含权限模型与管理员账号 |
| 运营管理员 | 用户/悬赏/配置/职司审批与撤销/公告 |
| 终裁仲裁员 | 纠纷终裁、改判审核结果 |
| （可选）观察者 | 只读日志与报表 |

侠士职司账号走 **执事堂（侠士端内的治理工作台）**，与 **武林盟管理后台** 分离；执事堂不得做成另一套冷色管理后台皮。

#### 6.13.7 设计原则（给研发/测试的约束）

1. **默认拒绝**：无职司、无管理员角色则无治理权。  
2. **授予权独占**：只有管理员能授/撤 L1。  
3. **核心不下放**：任何配置项不得把 L0 勾给侠士。  
4. **可审计**：谁在何时因何批准/撤销/审核，全部落库。  
5. **可接管**：管理员可随时接手任一审核单并改判。

### 6.14 告示栏

1. C 端提供 **告示栏** 入口（首页/导航常驻）；列表支持分类筛选。
2. **默认分类**：江湖规矩（平台规则）、防骗箴言、遵义租房须知、更新诏告。
3. 单条告示：标题、摘要、正文、是否置顶、生效/失效时间；支持富文本或 Markdown（实现自定）。
4. 关键路径露出：
   - 发令页、揭榜确认前可展示「防骗」置顶摘要链接；
   - **悬赏广场**常驻防骗箴言行（正文直出 + 过长滚动，见 §6.20.4）。
5. 仅管理员可发布/下架；职司无告示发布权（L0）。
6. **种子内容（上线必备，可由运营撰写）**：
   - 赏银托管与勿私下转账
   - 线下看房人身安全
   - 遵义租房常见费用结构（如押付习惯作科普，非法律承诺）
   - 假房源/假带看识别要点
   - 邀请制与职司说明（简版）

### 6.17 站内消息与未读（v1.7）

1. 侠士端提供消息中心（既有 `/messages`）；系统通知含：审核结果、结算、纠纷、赠银/奖励到账、职司相关等。
2. **未读标记（必须）**：
   - 全局导航「消息」入口显示 **未读数量角标**（0 则隐藏角标）；
   - 列表中未读项有视觉区分（红点/加粗/未读样式）；
   - 打开单条详情或执行「标记已读」后，该条未读清除，角标数量减少；
   - 「全部已读」可选，建议提供。
3. 未读数接口须可供布局轮询或登录后拉取（实现细节交架构）；前端不得只做列表而无角标。
4. 本项同时修复当前「页面上看不到未读标记」的产品缺陷。

## 7. 成长与经济体系

| 资产 | 称谓 | 规则（MVP / v1.7） |
|------|------|-------------|
| 现金（模拟） | 赏银 / 钱庄（**两**） | MVP **隐藏**用户充值/提现；注册 +500、邀新 +100（邀请人）、管理员发放；发令冻结（≥200）；结算 10% 服务费；超时退款 |
| 行动力 | 体力值 | 揭榜消耗；每日恢复免费额度；侠义值可兑换；不突破日揭榜 10 次 |
| 成长资源 | 侠义值 | 有效贡献才发放；可兑奖、兑体力；驱动 **等级晋升**；防刷 |
| 信誉资产 | 江湖声望 | 好评率 + 完成单量加权；令主协作中/待验收取消扣减（v1.8.8，见 §6.23.3）；驱动 **英雄谱·声望榜** 与盟主申请资格 |
| 荣誉顶点 | 武林盟主 | 声望榜首可申请；后台审批；唯一任 |

**核心机制**：

- 多人揭榜协作；令主按贡献分配；平台托管与结算；武林盟审核与仲裁。
- **赏银必须分完**：可分配池 100% 分配，防止令主故意少分截留。
- **成长目标**：侠义值升头衔 → 冲英雄谱 → 问鼎武林盟主。
- **银两纪律（v1.7）**：MVP 以发放制 + 悬赏流转为主；用户充值/提现暂时隐藏，非永久下线。

## 8. 非功能需求

- **性能**：支撑遵义小规模试运营；列表/详情/英雄谱流畅。
- **安全**：登录鉴权；管理员 RBAC 与侠士职司权限隔离；L0 不可下放；资金与调账防重放；审核/任免/授撤权/调账全量审计；提交限流。
- **可用性**：Web 响应式；主路径清晰；执事堂与管理后台职责分明，且执事堂视觉不脱离侠士端江湖气质。

- **可运营**：日常审核可交给职司；管理员聚焦监督、终裁与核心配置。

## 14. 武侠世界观 × 租房现实：均衡原则与补充建议

> 现状：机制层（悬赏、钱庄、声望、职司、英雄谱）已较完整；易偏「游戏壳」或「工具站」两端。本节给出 **均衡原则** 与 **建议补充**，用武侠名承载真实租房动作，避免空洞装扮。

### 14.1 均衡原则（产品宪法级）

| 原则 | 含义 | 反例（避免） |
|------|------|--------------|
| **一事两名** | 每个武侠玩法必须对应一个真实租房动作 | 只有「门派」「打怪」无找房价值 |
| **钱与法用法语** | 赏银、合同、退款、仲裁结论用清晰现代汉语；江湖词做包装不遮挡关键信息 | 支付页全文文言文导致误解 |
| **信任重于养成** | 先验真、再分配、后装扮；刷等级不能绕过审核与托管 | 靠肝体力升级却假房源横行 |
| **本地江湖** | 世界观落在遵义地理与租房语境，而非悬浮武侠宇宙 | 地图是开封洛阳，业务却在遵义 |
| **善意定价** | 赏银/侠义奖励匹配真实劳动（带看、核验），不鼓励无效刷榜 | 揭榜不做事也有收益 |
| **渐进沉浸** | MVP 先「术语+主线闭环」；堂口、茶馆、行侠录等按阶段加 | 首版功能树过大导致主线做不完 |

**映射口诀**：武侠名是皮肤，租房闭环是骨头；皮肤服务骨头，不另起一套游戏。

### 14.4 关键页面的「温度」建议（低成本高体感）

1. **空态与微文案**：无悬赏时「城中暂无新令，可张贴求援或稍后再来」；失败提示避免冷冰冰错误码。  
2. **完成反馈**：结算成功给短句「此单已结，赏银入账，声望已记」+ 现代明细。  
3. **令主引导**：发令末步提示「建议赏银覆盖带看交通与时间成本」，体现「不让善意吃亏」。  
4. **风险提示条**：涉及线下看房时固定提示人身与财产安全、不转账到私人规避托管等；悬赏广场防骗箴言行（§6.20.4）已覆盖常驻露出。
